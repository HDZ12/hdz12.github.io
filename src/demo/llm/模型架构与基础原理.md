## GPT 和 BERT 的架构有什么区别？各自适用于什么场景？
### 核心架构差异

| 维度 | GPT（Decoder-only） | BERT（Encoder-only） |
|--------|---------------------|----------------------|
| 注意力方向 | 单向（因果掩码，只看左侧上文） | 双向（可同时看左右上下文） |
| 训练目标 | 因果语言模型（Causal LM）：预测下一个 Token | 掩码语言模型（MLM）：预测被 `[MASK]` 遮挡的 Token |
| 核心模块 | Masked Self-Attention + FFN | Bidirectional Self-Attention + FFN |
| 输入可见范围 | 当前 Token 只能看到历史 Token | 每个 Token 可看到整个句子 |
| 擅长任务 | 文本生成、对话、代码生成 | 文本理解、分类、检索、NER |
| 推理方式 | 自回归（逐 Token 生成） | 一次性编码整个序列 |
| 代表模型 | GPT-3、GPT-4、Llama、Qwen | BERT、RoBERTa、ALBERT、DeBERTa |

## 注意力示意

### GPT（因果注意力）

```text
位置1 → ✓ ✗ ✗ ✗
位置2 → ✓ ✓ ✗ ✗
位置3 → ✓ ✓ ✓ ✗
位置4 → ✓ ✓ ✓ ✓
```

使用 **Causal Mask（因果掩码）**，禁止关注未来 Token。

### BERT（双向注意力）

```text
位置1 → ✓ ✓ ✓ ✓
位置2 → ✓ ✓ ✓ ✓
位置3 → ✓ ✓ ✓ ✓
位置4 → ✓ ✓ ✓ ✓
```

所有位置之间都可以互相注意。

## 本质区别

GPT 学习的是：

$$
P(x_t \mid x_1, x_2, \ldots, x_{t-1})
$$

即：

> 根据过去预测未来。

BERT 学习的是：

$$
P(x_i \mid x_1, \ldots, x_{i-1}, x_{i+1}, \ldots, x_n)
$$

即：

> 根据左右上下文预测被遮盖的词。

即：

> 根据上下文恢复缺失词。

因此：

- **GPT = 生成模型（Generative Model）**
- **BERT = 表征模型（Representation Model）**
### 为什么当前大模型主流选择 Decoder-only？
统一范式：生成式框架可以通过 prompt engineering 统一处理理解和生成任务
扩展性：Decoder-only 架构在 scaling law 下表现更优
训练效率：每个 token 都参与 loss 计算，数据利用率高（BERT 只有约 15% 的 [MASK] token 贡献 loss）
## LaynerNorm和BatchNorm的区别
## 归一化维度的核心区别

对于输入张量：

$$
X \in \mathbb{R}^{B \times T \times D}
$$

其中：

- $B$：batch size
- $T$：序列长度
- $D$：特征维度

---

### BatchNorm

**BatchNorm 在 batch 维度上归一化**：

对同一特征位置，跨所有样本计算均值和方差。

$$
\hat{x}_{:,:,d}=
\frac{x_{:,:,d}-\mu_d}{\sqrt{\sigma_d^2+\epsilon}}
$$

其中：

$$
\mu_d=\frac{1}{B \cdot T}\sum_{b,t}x_{b,t,d}
$$

含义是：  
BatchNorm 会对第 $d$ 个特征，在所有 batch 和所有 token 位置上统计均值和方差。

---

### LayerNorm

**LayerNorm 在特征维度上归一化**：

对同一样本的同一位置，跨所有特征计算均值和方差。

$$
\hat{x}_{b,t,:}=
\frac{x_{b,t,:}-\mu_{b,t}}{\sqrt{\sigma_{b,t}^2+\epsilon}}
$$

其中：

$$
\mu_{b,t}=\frac{1}{D}\sum_d x_{b,t,d}
$$

含义是：  
LayerNorm 会对某个样本中某个 token 的所有特征维度进行归一化。

---

## 为什么 Transformer 不用 BatchNorm

### 1. 序列长度变化问题

NLP 任务中序列长度通常不一致。  
BatchNorm 需要对同一位置跨 batch 统计，但不同样本的第 $t$ 个 token 语义可能完全不同。

例如：

- 第 5 个 token 可能是名词
- 第 5 个 token 可能是动词
- 第 5 个 token 也可能是标点符号

因此，跨样本统计同一位置的均值和方差，在 NLP 中语义意义不强。

---

### 2. 训练和推理不一致

BatchNorm 在推理时使用训练阶段累积的全局均值和方差：

$$
\text{running mean}, \quad \text{running variance}
$$

但在 NLP 中存在两个问题：

- 推理时的序列分布可能与训练时差异较大
- 当 batch size 为 1 时，BatchNorm 效果会变差甚至退化

---

### 3. 小 batch 性能差

大模型训练时常使用梯度累积来模拟大 batch，但实际每一步的 micro-batch 可能很小。

BatchNorm 在小 batch 下统计量噪声较大，因此性能容易下降。

---

### 4. LayerNorm 的天然优势

LayerNorm 更适合 Transformer，主要原因是：

- 每个样本独立归一化，不依赖 batch 中其他样本
- 训练和推理行为完全一致
- 不需要维护 running statistics
- 对序列长度变化天然鲁棒

---

## 数值示例

假设：

$$
D=4
$$

某个 token 的特征向量为：

$$
x=[1,3,5,7]
$$

计算均值：

$$
\mu=\frac{1+3+5+7}{4}=4
$$

计算方差：

$$
\sigma^2=
\frac{(1-4)^2+(3-4)^2+(5-4)^2+(7-4)^2}{4}=5
$$

因此：

$$
\text{LN}(x)=
\frac{[1,3,5,7]-4}{\sqrt{5}}
$$

得到：

$$
\text{LN}(x)=[-1.34,-0.45,0.45,1.34]
$$
## 大语言模型的涌现能力（Emergent Abilities）

## 1. 定义

**涌现能力**是指：

> 在小模型上不存在，或表现接近随机；但当模型规模超过某个临界点后，突然出现的能力。

这一现象类似物理学中的**相变现象**（phase transition）。  
例如，水在 $0^\circ C$ 附近会从液态转变为固态。

Google 研究团队在 2022 年正式提出这一概念：

> "An ability is emergent if it is not present in smaller models but is present in larger models."

即：

> 如果某种能力在小模型中不存在，但在大模型中出现，那么这种能力就是涌现能力。

---

## 2. 典型涌现能力示例

| 能力 | 临界规模（约） | 说明 |
|---|---:|---|
| Few-shot 思维链（CoT） | $\sim 100B$ 参数 | 小模型使用 CoT 可能反而性能下降 |
| 多步数学推理 | $\sim 60B+$ | 例如 GSM8K 数学推理基准 |
| 指令遵循 | $\sim 10B+$ | 能理解并执行复杂指令 |
| 代码生成 | $\sim 60B+$ | 例如 HumanEval 代码生成基准 |

---

## 3. 理解涌现的几种视角

### 3.1 表示能力的积累

模型在小规模时，可能已经部分学会了一些子技能，例如：

- 算术能力
- 逻辑推理能力
- 语言理解能力
- 任务分解能力

但这些子技能还不足以组合完成复杂任务。

当模型规模超过某个临界点后，多个子技能可以被有效组合，复杂任务能力就会突然表现出来。

可以用下面的形式理解：

$$
P(\text{complex task})=\prod_{i=1}^{n}P(\text{sub-skill}_i)
$$

也就是说，复杂任务的成功率取决于多个子技能的共同成功率。

例如，如果一个复杂任务需要 10 个子技能共同完成：

当每个子技能的成功率为 $0.7$ 时：

$$
0.7^{10}\approx 2.8\%
$$

当每个子技能的成功率提升到 $0.95$ 时：

$$
0.95^{10}\approx 59.9\%
$$

可以看到，单个子技能只是小幅提升，但组合后的整体成功率会出现明显跃升。

这就是涌现能力看起来“突然出现”的原因之一。

---

### 3.2 度量方式的假象

另一种观点认为，部分“涌现”可能并不是真正的能力突然出现，而是评价指标导致的非线性假象。

例如，在一些任务中使用的是：

> 精确匹配（Exact Match）

这种指标要求答案中的每个 token 都正确，只要有一个 token 错误，就会被判为整体错误。

因此，模型性能可能呈现出类似“阶梯式跳变”的现象。

如果换成更平滑的 token 级别指标，例如：

- BLEU
- token-level accuracy
- log probability

性能曲线可能会变得更加平滑。

这并不完全否定涌现能力的存在，而是提醒我们：

> 需要区分真正的能力涌现和评价指标造成的表面涌现。

---

### 3.3 训练数据多样性的作用

涌现能力不仅与参数量有关，也与训练数据的规模和多样性密切相关。

Chinchilla Scaling Law 表明：

> 模型规模和训练数据量需要同步增长。

如果模型参数很大，但训练数据不足，模型能力也无法充分发挥。

因此，涌现能力通常依赖于：

- 更大的参数规模
- 更丰富的训练数据
- 更长的训练时间
- 更合理的训练目标
- 更高质量的数据分布

---

## 4. 实际意义

### 4.1 小模型表现不能简单预测大模型

小模型在某些任务上表现不好，并不代表大模型也一定表现不好。

因为随着模型规模扩大，可能会出现能力上的质变。

也就是说：

> Scaling 不只是带来量的提升，也可能带来质的飞跃。

---

### 4.2 带来潜在安全隐患

涌现能力也可能带来安全问题。

模型在某个规模后，可能突然获得一些开发者没有预料到的能力，例如：

- 更强的推理能力
- 更强的代码生成能力
- 更强的策略规划能力
- 更强的欺骗或隐藏意图能力

因此，在训练大模型时，需要持续进行安全评估。

---

### 4.3 指导模型训练与评估

涌现能力说明，在模型训练过程中，不能只依赖小模型实验结果进行判断。

更合理的做法是：

- 在多个模型规模点上进行评估
- 观察能力随规模变化的趋势
- 关注是否存在突然跃升的能力
- 同时使用多种评价指标，避免度量假象

---

## 5. 总结

大语言模型的涌现能力可以概括为：

> 当模型规模、数据规模和训练复杂度达到一定程度后，模型可能突然表现出小模型不具备的复杂能力。

它说明大模型的能力增长并不总是线性的，而可能存在某些临界点。

但同时，涌现能力也存在争议。  
部分现象可能来自评价指标的非线性，而不一定是真正的能力突变。

因此，理解涌现能力时，需要同时考虑：

- 模型规模
- 数据规模
- 训练方式
- 评价指标
- 任务复杂度
